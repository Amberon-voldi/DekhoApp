# Dekho Affiliate Flow

The core monetization strategy for Dekho is affiliate marketing. When a user finds a product on Dekho and proceeds to buy it on a retailer's site, Dekho earns a commission on the sale.

This document details how the redirect and attribution flow works.

## The User Journey

1. **Discovery:** User views the "Compare Prices" section on the Product Detail Screen.
2. **Action:** User taps the "Buy Now" button on the Flipkart offer card.
3. **Trigger:** The Flutter app intercept the tap. Instead of launching Flipkart's URL directly, it makes a request to the Dekho backend.
4. **Processing (Backend):**
   - The app requests `GET https://api.dekho-app.com/v1/go/{offerId}`.
   - The backend looks up the `offerId`.
   - It records a "click event" in the analytics database (User ID, Offer ID, Timestamp, Device Info).
   - It retrieves the raw URL for the product on Flipkart.
   - It wraps the raw URL with the appropriate affiliate tracking parameters.
5. **Redirect:** The backend responds with an HTTP `302 Found` status, with the `Location` header set to the final affiliate URL.
6. **Execution:** The Flutter app (using `url_launcher`) opens the `Location` URL.
7. **Resolution:** The OS intercepts the URL. If the Flipkart app is installed, it handles the deep link. Otherwise, it opens in the default browser. The affiliate cookie is set.

## Affiliate Networks

To maximize coverage across retailers, Dekho will integrate with multiple networks:

- **Direct Programs:**
  - Amazon Associates India (Appends `&tag=dekho-21` to URLs)
  - Flipkart Affiliate Program (Appends `&affid=dekho`)
- **Aggregators (Fallback):**
  - Cuelinks
  - Admitad
  - EarnKaro

The backend routing logic in the `/go/:offerId` endpoint will dynamically choose the network that offers the highest commission for that specific retailer and category at that moment.

## Commission Tracking & Attribution

- **Cookies/Device IDs:** Affiliate networks rely on cookies (web) or device fingerprinting/deep links (app-to-app).
- **Sub-IDs:** We will pass a unique click ID generated by our backend as a `sub-id` (e.g., `&subid=clk_987654321`) to the affiliate network.
- **Postbacks:** When a sale occurs, the affiliate network fires a postback (webhook) to Dekho's server containing the `subid`.
- **Reconciliation:** We match the `subid` to the original user click to track which users, categories, and products are generating revenue.

## App Implementation Notes
In Phase 1 (Mock Data), the `RetailerOffer.url` simply contains a direct URL. The UI uses the `url_launcher` package to open it.

```dart
// Phase 1 implementation inside RetailerOfferCard
void _onBuyNow() async {
  final url = Uri.parse(offer.url);
  if (await canLaunchUrl(url)) {
    await launchUrl(url, mode: LaunchMode.externalApplication);
  }
}
```

In Phase 2, `offer.url` will be replaced with our `/go/` endpoint URL.
